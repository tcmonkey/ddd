# 开发计划：Java DDD 公共代码规范模板

> 用户已授权按计划直接编码。参考工程使用 `Ddd*` 中性占位符，不承载任何真实业务；本计划用于记录实现顺序、自测和偏差，不设置额外开发阻塞。

## 1. 实施策略与顺序

先建立 8 个 Maven module 及单向依赖，再实现 domain 模型和端口，随后接入 MyBatis-Plus 基础设施、application 编排、input/output adaptor，最后用领域测试和跨模块接口测试验证五条参考链路。纯计算模式不得依赖仓储或聚合；真实项目必须以领域语言替换 `Ddd*` 并按复杂度删减不适用模式。

## 3. 数据与配置变更

- 主聚合的单张 `ddd_data` 表保存聚合主状态及完整实体快照：`id`、`current_value`、`version`、`entities_json`。
- 规则聚合独立使用 `ddd_rule` 空表保存 `rule_code`、`factor`、`reason`；模板运行环境不预置 `DEFAULT`、`DOUBLE` 等演示规则，测试样本只由集成测试插入。
- H2 仅用于模板自测，应用重启后数据清空；生产项目应重新设计表名、字段、唯一索引和迁移脚本。
- `Application` 通过 `@MapperScan` 注册 Mapper；Mapper 不逐个标注 `@Mapper`。
- application、Controller、output adaptor 与 repository 的显式依赖均使用单一构造器注入。MyBatis-Plus `CrudRepository` 已为 Mapper 字段标记 `@Autowired`，基类和仓储子类不重复声明 Mapper 构造器；`DddRepositoryImpl` 的 `ObjectMapper` 使用构造器注入。domain service 保持无 Spring 依赖的 `@DomainService`，由 start 定向扫描并以单一普通构造器接收领域端口。
- 当前写入口刻意展示“按 operationId 幂等的新增或更新”，因此领域服务读取聚合后再决定重复返回或保存。未来纯新增用例应单独提供语义明确的 `create` 领域服务方法，直接初始化并保存，不机械复用查询步骤。
- `DddInputAssembler` 使用 `@Component` 直接注册；写应用以 `Instant.now()` 获取当前时间。模板不保留仅用于注册这两个对象的 `DddConfiguration`。
- Logback 由 `ddd-start/src/main/resources/logback-spring.xml` 配置。默认只输出控制台；`prod` 同时输出滚动文件，默认 `logs/ddd.log`。`LOG_DIR` 和 `ROOT_LOG_LEVEL` 可覆盖目录及根级别，`logs/` 已加入 Git 忽略规则。

## 4. 兼容与迁移步骤

1. 复制或参考模块结构，不直接把模板当成已经完成的业务实现。
2. 以业务统一语言替换 `Ddd` 前缀，例如 `DddReadApplication → OrderReadApplication`。
3. 重新定义 request/response/command/result、聚合不变量、仓储语义、API 和表结构；不要只做机械改名。
4. 仅保留真实需求需要的模式；例如没有外部调用时可不生成 output adaptor。
5. `Result<T>`、`Application`、模块边界和通用基础类保持已确认规范，除非目标仓库已有更高优先级约定。

## 5. 风险控制与回退点

| 风险 | 控制措施 | 回退方式 |
|---|---|---|
| 机械替换 `Ddd` 导致伪业务模型 | 真实项目先完成领域建模，再按聚合和用例命名。 | 删除不成立的生成类并回到技术方案修订。 |
| 四种模式被误认为全部必选 | 技术方案逐项标记适用或不适用。 | 移除不适用链路及依赖，不保留空壳类。 |
| 纯计算误接仓储 | 静态审查 `DddCalculateApplication` 和 `DddCalculateDomainService` 依赖。 | 回退为只接收值和因子的无状态实现。 |
| ORM 泄漏到 domain | domain 不引用 MyBatis-Plus 类型，repository 实现在 infrastructure。 | 将 ORM 类型和转换逻辑移回 infrastructure。 |
| 单表 JSON 快照被机械复制到真实业务 | 明确此处只演示聚合实体重建；真实项目先评估 JSON 查询、索引、体积、演进和迁移。 | 若不满足真实数据访问需求，改为关系表或专用存储，不照搬示例。 |
| 后续规范继续收紧 | 每项变更关联输入来源、设计 ID 和自测证据。 | 保留本项目修订记录，确认后再沉淀 Skill。 |
